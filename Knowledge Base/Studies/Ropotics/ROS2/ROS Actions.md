В [[Ros2]] **действия** представляют собой коммуникационный механизм, разработанный для длительных, целенаправленных задач, требующих обратной связи и возможности отмены или прерывания. Они построены на [[ROS Topic|топиках]] и [[ROS Services|сервисах]], предлагая более надёжное решение для сложных операций по сравнению с простыми **сервисами**.

### 1. Цель:

- Для управления задачами, выполнение которых занимает значительное время, такими как навигация робота, последовательности манипуляций или сложная обработка данных.
- Предоставлять запрашивающей стороне (клиенту) постоянную обратную связь о ходе выполнения задачи.
- Чтобы позволить клиенту отменить или изменить цель во время выполнения.

### 2. Компоненты:

- **Сервер действий:** 

Узел, который получает запросы на достижение цели, выполняет длительную задачу, предоставляет обратную связь о ходе её выполнения и отправляет окончательный результат по завершении. Он также обрабатывает запросы на отмену или прерывание.

- **Действие Клиента:** 

Узел, который отправляет запросы на цели на сервер действий, получает обратную связь в ходе выполнения задачи и, в конечном итоге, получает конечный результат. Он также может отправлять запросы на отмену.


### 3. Определение действия:

Действие определяется файлом `.action`, в котором указаны три типа сообщений:

- **Цель:** 

Входное сообщение, отправляемое клиентом серверу, определяющее желаемый результат действия.

- **Обратная связь:** 

Сообщения, периодически отправляемые сервером клиенту, содержащие обновления о ходе выполнения задачи.

- **Результат:** 

Последнее сообщение, отправляемое сервером клиенту, в котором указывается результат действия (успех, неудача и т. д.) и любые соответствующие данные.


### 4. Ключевые характеристики:

- **Асинхронно:** клиент отправляет цель и продолжает свои операции, пока сервер выполняет действие.
- **Возможность прерывания/отмены:** клиент может в любой момент отменить или прервать текущее действие.
- **Механизм обратной связи:** обеспечивает непрерывные обновления информации о ходе выполнения задачи, позволяя клиенту отслеживать ход выполнения и реагировать.
- **Модель клиент-сервер:** похожа на службы, но расширена для длительных задач.


### Пример использования:

Навигационная система робота может использовать действие для перемещения робота в заданную точку маршрута. Клиент действия отправит цель с координатами цели. Сервер действий, работающий в навигационной подсистеме, затем будет направлять робота, отправляя обратную связь о его текущем положении и ходе выполнения. При возникновении новой, более срочной задачи клиент может прервать текущее навигационное действие.

### **Команды взаимодействия с нодами:**

#### 1. Список всех действий
``` bash
ros2 action list
```
Детальный просмотр доступен с фалгом `-t`
``` bash
ros2 action list -t
```
#### 2. Информация о действии
``` bash
ros2 action info <action_name>
```
#### 3. Информация о типе данных для действий
``` bash
ros2 interface show <action_name>
```
#### 4. Задать цель для действия
``` bash
ros2 action send_goal <action_name> <action_type> <goal>
```
