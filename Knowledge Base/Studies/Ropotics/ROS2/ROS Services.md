В [[Ros2]] **сервисы** представляют собой механизм взаимодействия между [[ROS Node|нодами]] по принципу «**запрос-ответ»**, в отличие от модели [[ROS Topic|топиков]] «издатель-подписчик». Они используются для удалённых вызовов процедур, когда клиентский узел отправляет запрос узлу-серверу сервиса и ожидает ответа.

## **Ключевые характеристики сервисов ROS 2:**

### **Модель «запрос-ответ»:** 
Клиент отправляет запрос серверу и ожидает ответа. Сервер выполняет вычисления на основе запроса и отправляет ответное сообщение.
### **Синхронная коммуникация:** 
Клиент обычно ждет ответа от сервера, что делает этот метод подходящим для задач, где требуются немедленные результаты.
### **Определение услуги:** 
Сервисы определяются файлом `.srv`, который определяет структуру как запросов, так и ответов. Этот файл обычно находится в `srv` каталоге пакета ROS2.
### **Сервер обслуживания:** 
Узел, предоставляющий услугу, реализующий логику обработки запросов и генерации ответов.
### **Клиент службы:** 
Узел, который вызывает службу, предоставляемую сервером, отправляя запрос и получая ответ.
### **Варианты использования:** 
Сервисы идеально подходят для задач, требующих выполнения определенных вычислений или действий и возврата результата, например:
- Запрос информации (например, получение значения параметра).
- Запуск действия (например, очистка дисплея, создание объекта).
- Выполнение быстрого расчета.

#### 1. Список всех сервисов.
``` bash
ros2 service list
```
Детальный просмотр доступен с фалгом `-t`
``` bash
ros2 service list -t
```
#### 2. Отобразить список сервисов с определенным типом.
``` bash
ros2 service find <service_type>
``` 
#### 3. Просмотр интерфейса сервиса.
``` bash
ros2 interface show <service_type>
```
#### 5. Вызов интерфейса.
``` bash
ros2 service call <service_name> <service_type>
```
	В ответ получим ответ от сервиса, какбудто мы подписчик.
